# 测试（Writing Tests）

## 概述

测试怎么写：**TDD 纪律（何时写）** + **测试技法（怎么写好）**——测试类型、测什么/不测什么、结构、隔离、覆盖判断。语言无关；各语言测试框架（Vitest / Go testing / gtest / busted）归项目 AGENTS.md。

## 根本原则

**先写测试，再看它失败，再写最小实现，再看它通过。** 没有"先实现后补测试"的例外。测试是为"可回归、可信任"服务的，不是凑覆盖率。

## 何时使用

- 准备实现一个子任务，在写实现代码之前
- 需要把验收标准转成可执行测试

**何时不用**：纯文档、配置等无法测试的改动——在验收步骤说明为何不可测。

## 一、TDD 纪律（何时写）

1. 根据子任务的验收标准写测试。
2. 运行测试，看它失败（确认测试有效）。
3. 写最小实现让测试通过。
4. 运行测试，确认通过。

## 二、测试类型（金字塔）

| 类型 | 测什么 | 数量 / 速度 |
|---|---|---|
| 单元测试 | 单个函数/模块，mock 外部依赖 | 最多、最快 |
| 集成测试 | 模块间协作（真实数据库/服务） | 中等 |
| E2E 测试 | 用户路径（浏览器/真实服务） | 最少、最慢 |

比例：多数单元、少量集成、关键路径 E2E。**别把 E2E 当主力**——慢且脆。

## 三、测什么 / 不测什么

- **测**：业务逻辑、边界条件、错误路径、契约。
- **不测**：框架本身、实现细节（重构不应打碎测试）、纯视觉。

判据：这段逻辑删了或改错了，用户会不会受害？会 → 值得测。

## 四、怎么写

- **AAA 结构**：Arrange（准备）→ Act（执行）→ Assert（断言），一个测试一个行为。
- **命名**：用例名用**中文直接描述**，写清"测什么、什么场景、期望什么"（如 `按关键词过滤`、`空数据时显示空态`、`拒绝不存在的 id`），**不要加 should / 应 这类前缀**。
- **隔离**：每个测试独立、不依赖执行顺序、mock 外部依赖。
- **fixture / 测试数据**：独立文件，不硬编码在测试里。
- **测试只断言行为，不断言实现**。

## 五、覆盖判断

- 不是 100% 覆盖率，是**关键路径 + 高风险**覆盖。
- 判据：**删掉这段代码，有没有测试会红？** 没有 = 这段没被保护。

## 常见错误 / 红旗

- 先实现后补测试
- 只测正常路径，不测错误/边界
- 测试依赖实现细节，重构就碎
- 测了框架、没测业务逻辑
- 一个测试干太多事（不隔离、依赖顺序）
- "这个太简单不用测"

## 合理化借口表

| 借口 | 反驳 |
|---|---|
| "先写坏再修好，实现后补测试也一样" | 测试先行表达"应该做什么"；后补只描述"做了什么"，易流于形式 |
| "这么小的 bug 不用写测试" | 简单代码也会回归；最小测试成本 30 秒 |
| "E2E 覆盖了就够" | E2E 慢且脆；主力应是单元测试，E2E 只保关键路径 |
| "覆盖率 100% 才算测过" | 覆盖率不是目标；判据是"删掉这段代码有没有测试会红" |
