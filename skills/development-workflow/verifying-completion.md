# 完成前验收（Verifying Completion）

## 概述

子任务实现并测试通过后，宣称"完成"之前，按需求对话产出的验收标准逐条自验；中/高复杂度还需人最终确认。

## 根本原则

**没有按验收标准对账，就没有"完成"。** 跳过验收就宣称完成，是质量红线。

**没有证据的完成 = 未完成。** 每条验收结论必须附证据（测试输出 / 文件列表 / 手工验证记录），拿不出证据就是没完成。

## 何时使用

- 子任务已实现、测试通过，准备宣称完成
- 需要确认是否真的满足验收标准

## 验收步骤

1. 逐条对照验收标准，每条附证据（测试输出 / 文件列表 / 手工验证记录）。
2. 低复杂度：AI 自验通过即完成。
3. 中/高复杂度：AI 自验后，交人最终确认。

## 常见错误 / 红旗

- 跳过验收就宣称"完成/通过/已修复"
- 验收标准模糊，用"看起来没问题"代替对账
- 中/高复杂度跳过人确认
- 测试通过就当验收通过（测试 ≠ 验收标准全覆盖）
- "已完成但拿不出证据" —— 视为未完成
