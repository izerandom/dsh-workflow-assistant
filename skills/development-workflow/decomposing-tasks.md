# 任务拆分（Decomposing Tasks）

## 概述

把一个内聚需求拆成可独立实现、测试、验收的子任务。每个子任务 = 一个清晰目的 + 可测试接口 + 可观察验收。

## 根本原则

**一次只做一个子任务。** 拆完按顺序逐个走"完成 → 测试 → 验收"循环，不并行打散。

## 何时使用

- 需求已澄清、接口已设计，准备进入实现循环
- 一个需求明显由多个独立子任务组成（如 CRUD）

**何时不用**：低复杂度单点小改——不需要拆分，直接实现。

## 拆分原则

1. 每个子任务 = 一个清晰目的，接口明确，可独立测试。
2. **按功能/模块边界切，不按文件切**——这是并行不冲突的前提。
3. 子任务之间依赖清晰，按依赖排序。
4. 每个子任务绑定自己的验收标准（能写进测试）。
5. 每个切片产出**测试用例**（正常 / 边界 / 错误路径），回填工作单**第 5 节测试用例清单**，供人工评审。

## 常见错误 / 红旗

- 拆分过细（每个文件一个任务）或过粗（一个大任务装不下）
- 子任务之间隐性耦合，无法独立测试
- 拆完不排序，依赖乱的先做
- 子任务没有验收标准，循环末端无法验收
- 切片没有测试用例，评审时无法判断怎么测

## 合理化借口表

| 借口 | 反驳 |
|---|---|
| "一口气全做完更快" | 一批不相关需求先需求级拆分、一次只做一个 |
| "按文件切更细更好" | 切片按功能/模块边界切，不按文件切 |
